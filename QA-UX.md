# Независимый UX, accessibility и performance audit

Проверка 1 октября 2026 UTC: исходники `src/main.tsx`, `src/style.css`, `src/core.ts` и реальная production-сборка на локальном Vite preview. Использованы только искусственные данные. Автор аудита не менял исходники, конфигурацию проекта или существующие тесты; исправления внёс основной разработчик, после чего выполнена повторная проверка.

## Результат

Блокирующих UX-проблем в проверенном workflow не осталось. Проверены Chromium, Firefox и WebKit при desktop viewport 1440×1000 и narrow viewport 390×844. Для Chromium/WebKit включена mobile emulation и touch; для Firefox — узкий viewport и touch. Это не физические телефоны. WebKit здесь означает движок Playwright, а не проверку Safari.

Повторный независимый аудит: 36 сканирований axe (по шесть состояний в каждом сочетании движка/размера) с тегами `wcag2a`, `wcag2aa`, `wcag21aa`, без обнаруженных нарушений. Состояния: пустой workspace, demo, инспектор записи, предпросмотр правила, экспорт, структурная ошибка CSV. Проверены keyboard skip-link, видимый focus, открытие dialog клавишей Enter, закрытие Escape и возврат focus к вызвавшей кнопке. Горизонтального overflow документа при проверенных размерах нет; CSV-сетка и таблица предпросмотра прокручиваются в своих областях. Автоматический axe и эти ручные проверки не являются полной сертификацией WCAG или проверкой с экранным читателем.

| Проблема | Воспроизведение | Исправление и статус |

| Структурные ошибки скрывались onboarding-панелью | Импорт `sku,name\n1,a,EXTRA\n2,b` без проверок колонок: «Проблемы 1», но список пуст | Структурная issue отображается сразу; issue card 1, PASS |

## Проверенный полезный workflow

На Chromium и WebKit независимо пройден полный сценарий на обоих размерах: demo → выбор issue к stock записи №5 → trim / collapse whitespace / lower status с предпросмотром → выбор записи №2 из пары SKU-дубликатов → исправление stock и отсутствующего SKU → ручное исключение / undo / redo / возврат → четыре экспорта → повторный импорт clean CSV.

Числа соответствуют реальным данным: сначала 12 записей = 6 готовых + 6 требующих решения; после трёх правил 7 + 5; после разрешения дубликата и правок 11 + 1. Ручное исключение меняет результат на 10 + 2, undo возвращает 11 + 1, redo снова 10 + 2. Clean CSV содержит 11 записей; rejected — запись №4 с причиной; JSON report содержит ready 11 / rejected 1; recipe содержит три правила. Leading-zero SKU `00124` и большой идентификатор `90071992547409931234` сохранены. Реимпорт clean CSV показывает 11 записей без потерь. Page errors не обнаружены. Для Firefox отдельно повторены issue selection, keyboard/dialogs, структурная ошибка и большая вставка; полный cross-browser acceptance matrix ведёт основной набор E2E проекта.

Понятная формульная защита, настройки delimiter / BOM / CRLF, предупреждение о содержании rejected и отдельный opt-in хранения доступны в интерфейсе. На narrow viewport все действия доступны через обычную вертикальную прокрутку; таблица сохраняет горизонтальную прокрутку. Recipe расположен после таблицы и инспектора, поэтому мобильный workflow требует больше прокрутки, чем desktop.

## Реальные измерения производительности

Однократные локальные измерения Chromium на этом компьютере; величины включают действие автоматизации, worker и UI. Они зависят от устройства и нагрузки, а не гарантируют скорость всем пользователям.

| Искусственный CSV | Вход | Import → результат → render | Rule preview | Применить правило | Поиск | Export → download |
|---|---:|---:|---:|---:|---:|---:|
| 10 000 × 3 колонки | 120 014 байт | 486 мс | 435 мс | 443 мс | 50 мс | 810 мс |
| 10 000 × 50 колонок, 500 000 ячеек | 1 060 289 байт | 2 952 мс | 2 706 мс | 2 323 мс | 203 мс | 803 мс |

В обоих случаях DOM-сетка содержит только 20 записей. Максимальный наблюдённый main-thread long task — 54 мс для трёх колонок и 260 мс для 50 колонок. Worker не делает все UI-операции бесплатными: большой grid всё ещё требует render, а JSON/CSV export выполняется в основном потоке.

Финальная повторная проверка после исправления paste: 10 000 строк / 297 794 байта, во всех трёх движках event обработан с `preventDefault`, импорт содержит 10 000 записей, DOM-сетка — 20.

| Движок / версия | Paste → React state | Parse → worker → render |
|---|---:|---:|
| Chromium 148.0.7778.96 | 441 мс | 538 мс |
| Firefox 150.0.2 | 608 мс | 655 мс |
| WebKit 26.4 | 644 мс | 863 мс |

В отдельном Firefox narrow-viewport прогоне получено 268 мс input + 318 мс parse/worker/render. Использован синтетический browser paste event с plain-text clipboardData, а не физический clipboard. Большие `.fill` / `keyboard.insertText` не генерируют `paste` event и не подходят для проверки нового fast path.

## Границы проверки и evidence

Сохраняются реальные продуктовые ограничения: вход 2 МБ, 10 000 записей, 100 колонок, 500 000 ячеек; очищенные значения до 8 МБ. Проверена граница 500 000 ячеек, а не произвольные unlimited файлы. Generated CSV может быть больше входа из-за кавычек/BOM; повторный импорт также обязан укладываться во входные лимиты. Offline после первой загрузки, screen reader, физические телефоны и Safari отдельно не проверялись этим аудитом. Live deployment проверяется отдельным финальным прогоном основного разработчика; локальный review не подменяет live verification.

Firefox в restricted execution падал при создании страницы до загрузки сайта с `_page` TypeError. Те же независимые tests с разрешённым `require_escalated` прошли на Firefox 150.0.2 и временных headless profiles. Это ограничение среды выполнения, а не обнаруженная проблема Rowline; существующие пользовательские browser profiles не использовались.
